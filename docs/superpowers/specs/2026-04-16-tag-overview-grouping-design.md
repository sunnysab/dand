# 标签总览自动分组合并设计

**目标**

在 `/tags/` 标签总览页中，自动把公开文章集合完全相同的标签合并为同一行展示，并保留每个标签各自独立的链接，例如：

`新东方 & 新概念英语 ... 19 篇`

其中 `新东方` 和 `新概念英语` 都仍然可以分别点击进入自己的标签详情页。

## 现状

- `src/index.rs` 中的 `TagOverviewRenderer` 和 `CategoryOverviewRenderer` 目前共用 `ArchiveOverviewItem`
- `template/page/archive_list.html` 目前只支持单个链接项：`name + href + post_count`
- 当前标签总览页是一标签一行，无法表达“同一文章集合下的多个标签”
- 文章页标签展示、标签详情页生成、标签与文章的关联关系都已独立工作

## 决策

### 展示范围

本次只改标签总览页 `/tags/` 的展示方式：

- 标签总览页允许多个标签在同一行展示
- 文章页仍展示原始标签
- 每个标签详情页 `/tags/<slug>/` 仍然独立生成并可访问

原因：

- 需求本质上是总览页的信息压缩，不是 taxonomy 数据模型重构
- 保持现有标签详情页与文章页行为不变，风险最低

### 合并规则

自动按“公开文章集合完全相同”分组。

具体规则：

1. 对每个标签取其关联文章
2. 过滤掉 `draft` 和 `hidden`
3. 使用过滤后文章集合生成稳定签名
4. 签名相同的标签归为同一组

只有过滤后的公开文章集合完全一致时，多个标签才会在总览页同一行展示。

### 分组签名

分组签名必须基于稳定文章标识，而不是标题。

优先使用文章 slug；若当前代码中没有直接可用的 slug 访问方式，则退化为稳定输出路径或稳定 href。要求是：

- 唯一
- 稳定
- 不依赖可变文案

原因：

- 标题可能改名
- 标题不一定唯一
- 分组行为必须在内容不变时保持稳定

### 排序规则

组间排序：

- 先按 `post_count` 降序
- 再按组内第一个标签名升序

组内排序：

- 按标签名升序

原因：

- 保持与现有总览页“篇数优先”的信息层级一致
- 保证静态生成结果稳定，不因哈希表遍历顺序抖动

## 范围

### 本次处理

- 标签总览页按公开文章集合自动分组
- 同组标签以多个独立链接展示，中间用 ` & ` 连接
- 分类总览页继续保留单链接展示
- 归档总览相关结构按“分类专用”和“标签专用”拆分

### 本次不处理

- 标签数据层真正合并
- `dand.toml` 中增加手工标签合并配置
- 文章 front matter 改写
- 标签详情页合并成单一页面
- 文章页标签展示逻辑调整
- `Rc<RefCell>` 的标签/文章关系模型改造

## 实现方案

### 1. 分类总览模型收窄为分类专用

在 `src/index.rs` 中将现有通用归档结构改为分类专用：

- `ArchiveOverviewItem` -> `CategoryOverviewItem`
- `build_archive_items(...)` -> `build_category_overview_items(...)`
- `render_archive_overview(...)` -> `render_category_overview(...)`

分类页的行为和当前保持一致，只是命名收窄，避免继续维持“伪通用抽象”。

### 2. 为标签总览增加专用 view model

在 `src/index.rs` 中新增：

- `TagOverviewLink { name, href }`
- `TagOverviewItem { links: Vec<TagOverviewLink>, post_count }`

并新增 `build_tag_overview_items(...)`，负责：

1. 遍历全部标签
2. 获取该标签的公开文章集合
3. 生成该集合的稳定签名
4. 用签名对标签分组
5. 为每组生成一个 `TagOverviewItem`
6. 过滤 `post_count == 0` 的组
7. 对结果做稳定排序

### 3. 标签总览使用专用模板

新增模板：

- `template/page/tag_archive_list.html`

分类总览保留单独模板：

- `template/page/category_archive_list.html`

标签模板中，每个分组项渲染为：

- 多个独立 `<a>` 链接
- 链接之间插入 ` & `
- 末尾展示一次 `{{ item.post_count }} 篇`

原因：

- 分类总览和标签总览的数据结构已不同
- 拆模板比在同一模板里塞分支更清晰、更易维护

### 4. `TagOverviewRenderer` 接入分组逻辑

`TagOverviewRenderer::html()` 不再复用分类页的单项构造逻辑，而是：

- 构造标签专用 items
- 调用标签专用渲染函数
- 渲染标签专用模板

`CategoryOverviewRenderer` 继续走分类专用逻辑。

## 边界行为

- 若某标签过滤后公开文章数为 0，则不出现在 `/tags/`
- 若两个标签当前公开文章集合相同，则同一行展示
- 若后续其中一个标签新增或减少文章，导致公开文章集合不再相同，则会自动拆分为两行
- 标签详情页仍然各自独立；同组展示不代表详情页共享

## 文件变更范围

### 主要修改

- `src/index.rs`
- `template/page/tag_archive_list.html`
- `template/page/category_archive_list.html`

### 预期不修改

- `src/post/tag.rs`

只有在实现时发现“文章稳定标识”无法从现有接口取得时，才考虑做最小化辅助方法补充。

## 风险与兼容性

- 如果分组签名依赖的文章标识不够稳定，会导致标签合并结果抖动
- 标签总览页从单链接改为多链接后，模板和样式需要确认在窄屏下仍然可读
- 两个语义不同但当前公开文章集合刚好相同的标签会自动并排显示；这是本次明确接受的自动行为

## 验证

### 自动验证

- `cargo build`
- `cargo test`

### 重点测试场景

1. 两个标签公开文章集合相同：
   - `/tags/` 中应显示为同一行
   - 且两条链接都存在

2. 两个标签原始集合不同，但过滤 `draft` / `hidden` 后公开文章集合相同：
   - 应正确合并

3. 两个标签原始集合相同，但其中一个新增一篇公开文章：
   - 应自动拆分为两行

4. 标签无公开文章：
   - 不应出现在 `/tags/`
